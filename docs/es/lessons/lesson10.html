📦 Lección 10: Dando vida al Inventario

En la lección anterior dejamos la mochila "bonita" pero vacía. Hoy vamos a programar su "cerebro". Dividiremos el trabajo en tres scripts que trabajan en equipo: el Cuadradito (Vista), la Mochila (Datos) y el Panel (Control).

1. El motor del cuadradito: InventoryUiSlot.gd

Cada cuadradito individual de la mochila necesita su propio script para gestionar tres cosas:

  • Mostrar el icono y la cantidad correctamente.
  • Detectar cuándo el jugador clica el botón.
  • Avisar (mediante señales) cuando queremos usar o tirar el objeto.

📜 Código entero del Cuadradito

Crea el script InventoryUiSlot.gd y copia este código en el nodo raíz de tu Slot:

extends Panel

@onready var item_visual = $CenterContainer/Panel/item_icon
@onready var item_amount = $CenterContainer/Panel/amount
@onready var usePanel = $UsePanel

var item_in_slot:itemSlot

signal use(item:itemSlot)
signal drop(item:itemSlot)

func _ready() -> void:
    usePanel.visible = false
    $Button.disabled = true
    
func update_slot(slot:itemSlot):
    if !slot.item:
        item_visual.visible=false
        item_amount.visible=false
    else:
        item_in_slot=slot
        item_visual.visible=true
        item_amount.visible=true
        item_visual.texture=slot.item.texture
        item_amount.text=str(slot.amount)
        $Button.disabled=false
    
func _on_button_pressed() -> void:
    if(usePanel.visible):
        usePanel.visible=false
    else:
        usePanel.visible=true
    
func _on_use_pressed() -> void:
    use.emit(item_in_slot)
    usePanel.visible=false

func _on_drop_pressed() -> void:
    drop.emit(item_in_slot)
    usePanel.visible=false

Explicación del código del Slot:

  • Variables @onready: Conectamos los nodos visuales (icono, texto y el panel de opciones) para que el código pueda cambiarlos.
  • La función update_slot: Es el corazón del sistema. Recibe la información del recurso itemSlot. Si no hay nada, lo oculta todo para que el cuadradito se vea vacío; si hay un objeto, pone su textura y el número de cantidad.
  • Gestión del botón: El botón principal del slot sirve para mostrar u ocultar el UsePanel (el menú desplegable con "Usar" y "Tirar").
  • Las Señales (use y drop): Como el cuadradito no sabe qué hace una poción, simplemente "grita" hacia fuera: "¡Oye! ¡Quieren usar este ítem!".

2. El Cerebro de los Datos: Inv.gd

Este script no está en ninguna escena, está "dentro" del archivo de datos (tu `.tres`). Es el cerebro que organiza los objetos.

📜 Código del Recurso Inv

Este código se encarga de añadir y agrupar los objetos de manera automática:

extends Resource
class_name Inv

@export var slots:Array[itemSlot]

var inv_item:InvItem

signal inv_updated

func update_inv(item:InvItem):
    print(item)
    
    var inserted = false
    
    for slot in slots:
        if (slot.item!=null):
            if slot.item.name==item.name:
                slot.amount+=1
                inserted=true
                break
            
    if(!inserted):
        var empty_slot = slots.filter(func(slot):return (slot.item==null))
        
        if !empty_slot.is_empty():
            empty_slot[0].item=item
            empty_slot[0].amount=1
    
    inv_updated.emit()

¿Cómo gestiona los ítems? (update_inv)

Cuando Aina coge algo del suelo, este script hace tres pasos lógicos:

  • ¿Son iguales?: Mira si el ítem que acabamos de coger ya lo tenemos en la mochila. Si es así (por ejemplo, ya teníamos una poción), en lugar de gastar otro cuadradito, le suma 1 a la cantidad.
  • ¿Dónde hay sitio?: Si el ítem es completamente nuevo, busca el primer hueco que tenga el valor null (vacío). Lo hace utilizando la función .filter, que es como un colador de datos.
  • Avisar del cambio: Una vez guardado, emite la señal inv_updated. Esto es vital para que la interfaz sepa que tiene que refrescarse para mostrar los cambios.

3. El Orquestador: InventoryUi.gd

Este es el "Director" que tenemos en la pantalla. Une los datos con la imagen.

Sus funciones principales:

  • Conexión Inicial (_ready): Al abrir el juego, este script va slot por slot conectándose a sus señales de "Usar" y "Tirar"
    • .
  • También se conecta al Recurso del inventario. Abrir/Cerrar: Detecta la tecla "I" (o la que queramos) para mostrar u ocultar todo el panel.
  • Lógica de acciones (use_item): Aquí es donde decidimos qué pasa realmente. Por ejemplo: Si el objeto se llama "potion" $\rightarrow$ Llamamos a la función de curar. Si se llama "key" $\rightarrow$ Emitimos una señal hacia el escenario para abrir la puerta.

📜 Código Principal (InventoryUi.gd)

extends Control

@onready var ui_slots = $Background/GridContainer.get_children()
@export var inv:Inv

signal use_key

func _ready() -> void:
    inv.inv_updated.connect(update_inv_ui)
    
    for i in range(min(ui_slots.size(), inv.slots.size())):
        ui_slots[i].use.connect(use_item)
        ui_slots[i].drop.connect(drop_item)
    
    update_inv_ui()
    close()
    
func _unhandled_input(event: InputEvent) -> void:
    if Input.is_action_just_pressed("inventory"):
        if visible:
            close()
        else:
            open()    

func close():
    visible=false
    
func open():
    visible=true

func update_inv_ui():
    for i in range(min(ui_slots.size(), inv.slots.size())):
        ui_slots[i].update_slot(inv.slots[i])

func use_item(item:itemSlot):
    drop_item(item)
    # Añadir condicionales para los diferentes items según el nombre. Por ejemplo:
    # if (item.item.name=="key"):
    #     use_key.emit()
    
func drop_item(item:itemSlot):
    if item.amount>1:
        item.amount-=1
    else:
        var index=0
        while(index < inv.slots.size()):
            if inv.slots[index]==item:
                inv.slots.remove_at(index)
                break
            index+=1
    update_inv_ui()

¿Qué hace en resumen? Captura cuando pulsamos la tecla asignada en el mapa de acciones ("inventory") para abrir o cerrar la UI, escucha si algún botón ha emitido las señales use y drop, y automáticamente refresca las cantidades y los iconos en pantalla.

4. 🎒 Aina y su Mochila: La conexión final

Para que todo el sistema que hemos programado funcione, Aina tiene que ser la propietaria de la información y de la interfaz.

1. Equipando a Aina (Nodos y Recursos)

Dentro de la escena de nuestro personaje (Player.tscn), tenemos que hacer dos pasos fundamentales:

  • Añadir la UI: Arrastrad la escena InventariUI.tscn dentro de Aina (mejor si está dentro de un nodo CanvasLayer para que no se mueva con la cámara y siempre aparezca en el centro de la pantalla de forma perfecta).
  • Asignar los datos: Creamos la variable inventory con @export en el script de Aina y, en el Inspector de esta, le añadimos el recurso playerInv.tres arrastrándolo. De esta manera, Aina ya "tiene" una mochila física donde guardar cosas de golpe.

2. La función de Recogida (collect)

Dentro del script de Aina, necesitaremos una función llamada collect.

  • ¿Qué hace?: Esta función será la "puerta de entrada". Cuando Aina encuentre un objeto en el mundo, este objeto le "pasará" su archivo .tres correspondiente.
  • ¿Cómo funciona?: La función cogerá ese archivo en bruto y llamará al método update_inv de nuestra mochila para guardarlo oficialmente dentro a toda máquina.

🌍 Objetos en el Mundo: El camino del .tres

Para que Aina pueda recoger una llave o una poción saltando por el escenario, el objeto que vemos en la pantalla tiene que tener obligatoriamente dos cosas preparadas:

  • Una imagen (Sprite2D) y una Area2D con forma: Para que el juego sepa dónde está el objeto y cuándo lo tocamos.
  • Su propio archivo .tres: En el script del objeto del suelo, tenemos que tener un hueco en el Inspector de la variable del export para poner el recurso del ítem (por ejemplo, le arrastramos nuestro archivo clau.tres o pocio.tres).

El flujo por lo tanto es el siguiente:
Aina entra en el Area2D del objeto ➔ El objeto lanza el dato y dice: "¡Oye, Aina! Soy una llave, ¡aquí tienes mi recurso .tres!" ➔ Aina llama a su propia función collect() de pasada y lo guarda rápidamente. ¡Bam!

5. 🗝️ El Reto: La Puerta Bloqueada

Ahora que ya sabemos recoger objetos, vamos a ponerlo a prueba con un rompecabezas clásico.

¿Cómo hacer que una llave abra una puerta?

La llave por sí sola no sabe abrir puertas de manera mecánica; necesitamos que haya una comunicación entre la mochila de Aina y el escenario.

  • La Acción del Usuario: Cuando abrimos el inventario y clicamos en "Usar" sobre la llave de oro, el inventario tiene que emitir esa nueva señal explícita (por ejemplo, la señal use_key).
  • El Escenario escucha: Tenéis que conectar esa señal única de la UI (que actualmente está dentro de Aina) con el script de vuestro nivel principal o directamente a la misma puerta.
  • La Condición: La puerta solo se tiene que abrir o destrozar (haciendo queue_free() u ocultándose) exclusivamente si se ha recibido la señal de uso de la llave mágica.
