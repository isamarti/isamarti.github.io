💾 Lección 13: ¡No pierdas el progreso! (Guardar y Cargar)

Hasta ahora, cada vez que cerrábamos el juego de Aina, todo volvía a empezar. Hoy aprenderemos a crear un sistema de Save & Load para que el jugador pueda continuar su aventura exactamente donde la dejó.

1. El concepto: ¿Qué tenemos que guardar?

No hace falta guardar "todo" el juego, solo los datos que cambian. En nuestro RPG, lo más importante es:

  • La Posición: En qué pantalla (nivel) está Aina y en qué coordenadas X e Y.
  • El Inventario: Qué objetos .tres tiene y qué cantidad.
  • El Estado del mundo: ¿Se ha abierto ya la puerta de la Lección 10? ¿Hemos hablado ya con el NPC? ¿Cuánta vida le queda a Aina?

Lo que importa es decidir cuáles son los datos importantes para retomar el juego donde lo dejamos.

2. Guardar archivos: El formato JSON

Para guardar los datos, crearemos un diccionario en GDScript en el que iremos guardando los datos en el archivo Globals, y lo convertiremos a JSON para guardarlo en un archivo.

Ejemplo de qué guardaremos:

var game_data : Dictionary = {
	"playerHealth" : 100,
	"inventory":[],
	"last_screen":"bosque",
	"x_position":450,
	"y_position":320,
	}

Cada vez que alguno de estos datos cambia, se tiene que actualizar. Por ejemplo, cuando hacemos un update del inventory, tenemos que actualizar este al diccionario:

Código extra en el update_inventory para almacenar los datos al diccionario.

3. 📂 ¿Dónde se guardan los datos? res:// vs user://

En Godot, no usamos rutas de carpetas como C:\Documents\Juego... porque el juego tiene que funcionar igual en Windows, Mac, Linux o Android. Por eso, Godot usa "prefijos" especiales.

1. res:// (The Resources - El contenido del juego)

Este prefijo hace referencia a la carpeta de tu proyecto (donde tienes los sprites, la música y los scripts).

  • ¿Qué es?: Es el "paquete" del juego. Cuando publicas el juego y lo envías a un amigo, todo lo que hay dentro de res:// se convierte en un archivo comprimido que no se puede tocar.
  • Permisos: Es de SOLO LECTURA.
  • ¿Por qué?: Por seguridad. El sistema operativo (Windows, Android...) no deja que un programa se modifique a sí mismo mientras se ejecuta. Si intentaras guardar la partida dentro de res:// una vez publicado el juego, el programa daría un error o, simplemente, no guardaría nada.
  • Analogía: Es como un libro de texto. Puedes leerlo, pero no puedes escribir encima para cambiar lo que dice el tema 1.

2. user:// (The User Data - Los datos del jugador)

Este prefijo apunta a una carpeta especial que el sistema operativo reserva específicamente para que ese juego pueda escribir datos.

  • ¿Qué es?: Es el espacio privado del jugador en el disco duro. Dependiendo del sistema, estará en AppData (Windows) o en la carpeta Home (Linux/Mac).
  • Permisos: Tiene permisos de ESCRITURA Y LECTURA.
  • ¿Por qué?: Es el único sitio donde tenemos permiso para crear archivos nuevos (como partida.save o configuracion.cfg) sin que el antivirus o el sistema operativo nos bloquee.
  • Analogía: Es como tu libreta de notas. Está vacía cuando empiezas el curso, pero tú tienes el bolígrafo para ir apuntando todo lo que vas aprendiendo (o guardando tu progreso).

🛡️ Una lección de Seguridad Informática

¿Por qué los sistemas modernos funcionan así? Por dos motivos clave:

  • Protección contra Virus: Si un juego pudiera modificar sus propios archivos (res://), un programa malicioso podría "esconderse" dentro de un juego legítimo y cambiar su código sin que te dieras cuenta. Al separar los datos del usuario del código del programa, el sistema es más robusto.
  • Multiusuario: Varios jugadores pueden jugar al mismo juego en el mismo ordenador. El código del juego (res://) es el mismo para los dos, pero cada uno tendrá su propia carpeta user:// (dentro de su perfil de usuario). Así, tus partidas no se mezclan con las suyas.

💡 Cómo aplicarlo al código

Siempre que queráis guardar un archivo desde Godot, recordad empezar la ruta así:

var ruta = "user://partida_guardada.save"

Si intentáis hacerlo con res://, vuestro juego funcionará mientras lo editáis en Godot, pero fallará cuando lo convirtáis en un archivo ejecutable para repartirlo al resto de gente.

4. El proceso en 3 pasos

Paso A: Serializar (Escribir)

Crearemos una función en nuestro script Globals (o un nuevo script de SaveManager) que coja todas las variables importantes y las meta en un archivo dentro de la carpeta secreta de Godot: user://partida_guardada.save.

Guardar los datos 

func save_game()->void:
	var save_file = FileAccess.open(save_path,FileAccess.WRITE)
	save_file.store_var(game_data)
	save_file = null

Paso B: Deserializar (Leer)

Al iniciar el juego, buscaremos si ese archivo existe. Si existe, lo leeremos y sobrescribiremos las variables del juego con los datos del archivo.

Cargar los datos 

func load_game()->void:
	if FileAccess.file_exists(save_path):
		var save_file = FileAccess.open(save_path,FileAccess.READ)
		game_data = save_file.get_var()
        save_file=null

Paso C: El inventario es especial

Como nuestro inventario es un Resource (.tres), el truco más fácil es leer el array del diccionario y que el player haga un "collect" de cada Resource que encontremos en el diccionario.

Para cargar el nivel correcto, usaremos:
