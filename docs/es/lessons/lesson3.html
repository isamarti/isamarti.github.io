Lección 3: Control Total y Animaciones Complejas

En esta lección haremos que el jugador tome el control. Aprenderemos a abstraer las entradas de teclado y ratón para hacer el código más limpio y robusto, y utilizaremos herramientas profesionales de animación para dar vida a nuestro protagonista.

1. Abstracción de Entradas: El Input Map

Hasta ahora, hemos visto cómo el motor mueve objetos de forma automática (como el enemigo). Pero, ¿cómo hacemos que nuestro personaje responda a nuestras órdenes? El primer impulso de un programador principiante sería escribir una instrucción que diga: "Si se pulsa la tecla W, mueve el personaje hacia arriba". Sin embargo, en el desarrollo profesional de videojuegos usamos un concepto más inteligente llamado Abstracción mediante el Input Map (Mapa de Entradas).

¿Por qué no usamos teclas directamente?

Imaginad que un alumno quiere jugar con las flechas del teclado, otro con las teclas WASD y otro con un mando de consola. Si hubiéramos programado la tecla "W" directamente, el juego solo funcionaría para el primer alumno.

La solución: Crear "Acciones"

En lugar de preguntar "¿se ha pulsado la tecla W?", preguntaremos "¿se ha realizado la acción de moverse arriba?". Esto es una abstracción.

  1. Creamos la acción llamada "up".
  2. Dentro de la configuración de Godot, le decimos que esta acción se activa si se pulsa la "W", la "Flecha Arriba" o el "Stick del mando".
  3. En nuestro código, solo preguntaremos: "¿Se ha realizado la acción 'up'?".

Configurando el Input Map

  1. Ve al menú Project > Project Settings.
  2. Selecciona la pestaña Input Map.
  3. En la barra "Add New Action", escribe el nombre de la acción. Para este curso usaremos los nombres:
    • up
    • down
    • left
    • right
  4. Pulsa Add para crear cada acción.
  5. Al lado de cada acción nueva, pulsa el botón + para asignarle una tecla o botón.
  6. Pulsa la tecla que quieras (ej: W para up) y pulsa OK. Puedes añadir múltiples teclas para una misma acción (ej: W y Flecha Arriba).
💡 Nota Pedagógica: Este concepto es fundamental en informática. Separamos la "intención" (querer moverse) de la "implementación" (pulsar la tecla W). Esto hace que nuestro software sea más flexible y adaptable.

2. Creando el Personaje Principal (Player)

Igual que hicimos con el enemigo, crearemos una escena para nuestro personaje principal, nuestra heroína. Yo la llamaré Aina.

  1. Crea una nueva escena y elige CharacterBody2D como raíz. Llámalo Aina (o como tú quieras).
  2. Añade un CollisionShape2D y define su forma (normalmente una cápsula o rectángulo a los pies).
  3. Guarda la escena en la carpeta scenes/.

Para la imagen, esta vez no usaremos un simple Sprite2D ni un AnimatedSprite2D básico, sino algo más potente.

3. AnimationPlayer: Creando el Catálogo de Animaciones

El AnimationPlayer es el nodo fundamental para crear movimiento. Nos permite animar prácticamente cualquier propiedad de cualquier nodo de nuestro proyecto (posición, escala, rotación, color, o el frame de un Sprite).

Conceptos clave:

  • La Línea de Tiempo (Timeline): Es donde definimos la duración de la animación.
  • Fotogramas Clave (Keyframes): Son los puntos donde "fotografiamos" una propiedad. Si en el segundo 0 Aina está en la posición X=0 y en el segundo 1 está en X=100, Godot calculará automáticamente todos los pasos intermedios (interpolación).
  • Pistas (Tracks): Cada propiedad que animamos tiene su propia pista. Podemos tener una pista para el movimiento y otra para el sonido en la misma animación.

Paso a Paso: Sprite Sheet y AnimationPlayer

📥 Recursos de la lección: Puedes descargar el paquete de imágenes de Aina para empezar a crear tus animaciones aquí: aina.rar

También puedes buscar tus propios recursos en webs como opengameart.org o itch.io

  1. Añade un nodo Sprite2D a tu Player.
  2. Carga una "Sprite Sheet" (una hoja con todos los fotogrames del personaje) en la propiedad Texture. Asegúrate de configurar Hframes y Vframes según cuántas filas y columnas tenga tu imagen.
  3. Añade un nodo AnimationPlayer. Este nodo es el "director de orquesta" que controla qué fotogrames se muestran y cuándo.
  4. En el panel Animation (abajo), crea las nuevas animaciones: idle_down, walk_down, walk_up, etc.
  5. Para cada animación:
    • Define la duración (ej: 0.8 segundos).
    • Pulsa la llave al lado de la propiedad Frame del Sprite2D para grabar los fotogrames clave en la línea de tiempo.
    • Activa la opción de bucle (loop) si es una animación que se repite (como caminar).
Nota: El AnimationPlayer es perfecto para crear las animaciones individuales, pero para gestionarlas necesitaremos un sistema más inteligente.

4. AnimationTree: El Sistema Experto

Si el AnimationPlayer crea las animaciones, el AnimationTree es el sistema que las conecta y gestiona de forma inteligente. Nos permite crear lógicas complejas de movimiento sin escribir cientos de líneas de "if/else".

1. Tipos de Nodos Raíz (Tree Root)

Cuando configuramos un AnimationTree, tenemos que elegir cómo queremos organizar nuestras animaciones:

  • AnimationNodeStateMachine: Ideal para estados que se excluyen mutuamente (o estás quieto, o caminas, o atacas).
  • AnimationNodeBlendTree: Permite mezclar múltiples animaciones a la vez (por ejemplo, caminar mientras reproduces una animación de daño).
  • AnimationNodeBlendSpace2D: Utilizado dentro de los anteriores para gestionar direcciones (8 direcciones en un mapa 2D).
Opción Tipo de control Analogía pedagógica
StateMachine Lógica de estados Un mapa de ciudades y carreteras.
BlendSpace2D Direccionalidad Una brújula que apunta a la animación correcta.
BlendTree Mezcla modular Una mesa de mezclas de DJ donde combinas canales.

2. La combinación ganadora para Aina

Para un personaje que se mueve en 4 direcciones (como un RPG clásico), lo que hacemos normalmente es:

  1. Creamos una StateMachine como raíz.
  2. Dentro de la State Machine, en lugar de poner una animación simple de un AnimationPlayer, creamos un nodo de tipo BlendSpace2D y lo llamamos "Caminar".
  3. Hacemos lo mismo para "Parado" (Idle).

¿Por qué lo hacemos así?

  • La StateMachine se encarga de decidir si Aina está caminando o parada (la parte "macro" de la lógica).
  • El BlendSpace2D se encarga de decidir, si Aina está caminando, cuál de las 4 animaciones (arriba, abajo, izquierda, derecha) debe mostrar según el vector de movimiento (la parte "micro").
🧠 Utilizamos la StateMachine para organizar los conceptos (Parado vs. Caminando) y utilizamos el BlendSpace2D dentro de esos estados para gestionar las direcciones (Norte, Sur, Este, Oeste). Es como si la StateMachine fuera el mapa de carreteras y el BlendSpace2D fuera la brújula."

3. Paso a Paso: Configuración de la Máquina de Estados

  1. Añade un nodo AnimationTree al Player.
  2. Asígnale el AnimationPlayer que has creado antes.
  3. En Tree Root, selecciona New AnimationNodeStateMachine.
  4. Activa la casilla Active.

A. El BlendSpace2D (El espacio de mezcla)

Dentro del grafo de la máquina de estados, hacemos clic derecho y creamos un BlendSpace2D llamado Idle.

  • Ponemos la animación de "Idle Right" en el punto (1, 0) y "Idle Left" en el (-1, 0).
  • El nodo recibirá una dirección (Vector2) y elegirá la animación correcta automáticamente.

B. Transiciones y Condiciones de Avance

Las flechas que conectan estados (como de Idle a Walk) pueden ser de dos tipos:

  • Inmediatas: Cambian de estado tan pronto como lo pedimos por código (usando travel()).
  • Advance Conditions: Podemos crear variables booleanas en el inspector y conectarlas a las flechas. La animación cambiará sola cuando la variable sea true.

C. Parámetros y el Inspector

Uno de los puntos que más confunde a los principiantes es dónde se esconden las variables del árbol. Cuando creas un BlendSpace2D, aparecerá una nueva sección en el inspector del nodo llamada Parameters.

  • Playback: Es el objeto que usamos para viajar entre estados.
  • Blend Positions: Son los vectores que indican hacia dónde mira el personaje.

4. Las otras opciones del AnimationTree

Si exploras el menú, verás más opciones:

  • BlendSpace1D: Igual que el 2D, pero solo en un eje. Útil para un juego de plataformas lateral (izquierda/derecha).
  • AnimationNodeBlend2: Sirve para mezclar dos animaciones por porcentaje. Por ejemplo, si quieres que un personaje camine y esté herido a la vez, puedes mezclar las dos animaciones al 50%.
  • AnimationNodeOneShot: Para animaciones que solo pasan una vez y vuelven al estado anterior (como recibir un golpe o hacer un salto).
🧠 Concepto Avanzado: El AnimationTree funciona como un "filtro" entre nuestro código y el AnimationPlayer. El código solo dice la "intención" (velocidad: 100, dirección: derecha) y el árbol se encarga de elegir el fotograma exacto y hacer la transición suave.

5. El Código: Juntándolo todo

Finalmente, daremos vida a todo esto con un script en el nodo Player. 

extends CharacterBody2D

extends CharacterBody2D

@onready var tree: AnimationTree = $AnimationTree

@export var speed=150

var direction:Vector2

func _ready() -> void:
	tree.active=true
	
func _physics_process(delta: float) -> void:
	
	#En esta función tenemos en cuenta todos los procesos físicos, como caminar, etc
	direction = Input.get_vector("left", "right", "up","down").normalized()
	
	if(direction):
		velocity= direction*speed
		move_and_slide()
		
func _process(delta: float) -> void:
	update_animation_parameters()
	

func update_animation_parameters():
	#Si direction es Vector.Zero, Aina está parada, si no está en movimiento
	#Se actualizan los parámetros del árbol según direction
	
	if(direction==Vector2.ZERO):
		tree["parameters/conditions/idle"]=true
		tree["parameters/conditions/running"]=false
	else:
		tree["parameters/conditions/idle"]=false
		tree["parameters/conditions/running"]=true
		
	if(direction!=Vector2.ZERO):
		tree["parameters/idle/blend_position"]=direction
		tree["parameters/run/blend_position"]=direction

Fíjate lo limpio que queda el código gracias al AnimationTree. No tenemos que decirle "reproduce la animación walk_up", simplemente le decimos "estamos caminando hacia arriba" (la blend_position) y el árbol se encarga de hacer la transición fluida entre estados mediante el playback.
