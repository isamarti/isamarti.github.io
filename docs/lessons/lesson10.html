📦 Lliçó 10: Donant vida a l'Inventari

A la lliçó anterior vam deixar la motxilla "bonica" però buida. Avui anem a programar el seu "cervell". Dividirem la feina en tres scripts que treballen en equip: el Quadret (Vista), la Motxilla (Dades) i el Panell (Control).

1. El motor del quadret: InventoryUiSlot.gd

Cada quadret individual de la motxilla necessita el seu propi script per a gestionar tres coses:

  • Mostrar la icona i la quantitat correctament.
  • Detectar quan el jugador clica el botó.
  • Avisar (mitjançant senyals) quan volem usar o tirar l'objecte.

📜 Codi sencer del Quadret

Crea el script InventoryUiSlot.gd i copia aquest codi al node arrel del teu Slot:

extends Panel

@onready var item_visual = $CenterContainer/Panel/item_icon
@onready var item_amount = $CenterContainer/Panel/amount
@onready var usePanel = $UsePanel

var item_in_slot:itemSlot

signal use(item:itemSlot)
signal drop(item:itemSlot)

func _ready() -> void:
    usePanel.visible = false
    $Button.disabled = true
    
func update_slot(slot:itemSlot):
    if !slot.item:
        item_visual.visible=false
        item_amount.visible=false
    else:
        item_in_slot=slot
        item_visual.visible=true
        item_amount.visible=true
        item_visual.texture=slot.item.texture
        item_amount.text=str(slot.amount)
        $Button.disabled=false
    
func _on_button_pressed() -> void:
    if(usePanel.visible):
        usePanel.visible=false
    else:
        usePanel.visible=true
    
func _on_use_pressed() -> void:
    use.emit(item_in_slot)
    usePanel.visible=false

func _on_drop_pressed() -> void:
    drop.emit(item_in_slot)
    usePanel.visible=false

Explicació del codi del Slot:

  • Variables @onready: Connectem els nodes visuals (icona, text i el panell d'opcions) perquè el codi puga canviar-los.
  • La funció update_slot: És el cor del sistema. Rep la informació del recurs itemSlot. Si no hi ha res, ho amaga tot per a que el quadret es veja buit; si hi ha un objecte, posa la seua textura i el número de quantitat.
  • Gestió del botó: El botó principal del slot serveix per a mostrar o amagar el UsePanel (el menú desplegable amb "Usar" i "Tirar").
  • Les Senyals (use i drop): Com que el quadret no sap què fa una poció, simplement "crida" cap a fora: "Ei! Volen usar aquest ítem!".

2. El Cervell de les Dades: Inv.gd

Aquest script no està en cap escena, està "dins" del fitxer de dades (el teu `.tres`). És el cervell que organitza els objectes.

📜 Codi del Recurs Inv

Aquest codi s'encarrega d'afegir i agrupar els objectes de manera automàtica:

extends Resource
class_name Inv

@export var slots:Array[itemSlot]

var inv_item:InvItem

signal inv_updated

func update_inv(item:InvItem):
    print(item)
    
    var inserted = false
    
    for slot in slots:
        if (slot.item!=null):
            if slot.item.name==item.name:
                slot.amount+=1
                inserted=true
                break
            
    if(!inserted):
        var empty_slot = slots.filter(func(slot):return (slot.item==null))
        
        if !empty_slot.is_empty():
            empty_slot[0].item=item
            empty_slot[0].amount=1
    
    inv_updated.emit()

Com gestiona els ítems? (update_inv)

Quan l'Aina agafa algo del terra, aquest script fa tres passos lògics:

  • Són iguals?: Mira si l'ítem que acabem d'agafar ja el tenim a la motxilla. Si és així (per exemple, ja teníem una poció), en lloc de gastar un altre quadret, li suma 1 a la quantitat.
  • On hi ha lloc?: Si l'ítem és completament nou, busca el primer forat que tinga el valor null (buit). Ho fa utilitzant la funció .filter, que és com un colador de dades.
  • Avisar del canvi: Una vegada guardat, emet la senyal inv_updated. Això és vital perquè la interfície sàpiga que ha de refrescar-se per mostrar els canvis.

3. L'Orquestrador: InventoryUi.gd

Aquest és el "Director" que tenim a la pantalla. Uneix les dades amb la imatge.

Les seues funcions principals:

  • Connexió Inicial (_ready): En obrir el joc, aquest script va slot per slot connectant-se a les seues senyals de "Usar" i "Tirar"
    • .
  • També es connecta al Recurs de l'inventari.Obrir/Tancar: Detecta la tecla "I" (o la que vulguem) per a mostrar o amagar tot el panell.
  • Lògica d'accions (use_item): Ací és on decidim què passa realment. Per exemple: Si l'objecte es diu "potion" $\rightarrow$ Cridem a la funció de curar.Si es diu "key" $\rightarrow$ Emetem una senyal cap a l'escenari per a obrir la porta.

📜 Codi Principal (InventoryUi.gd)

extends Control

@onready var ui_slots = $Background/GridContainer.get_children()
@export var inv:Inv

signal use_key

func _ready() -> void:
    inv.inv_updated.connect(update_inv_ui)
    
    for i in range(min(ui_slots.size(), inv.slots.size())):
        ui_slots[i].use.connect(use_item)
        ui_slots[i].drop.connect(drop_item)
    
    update_inv_ui()
    close()
    
func _unhandled_input(event: InputEvent) -> void:
    if Input.is_action_just_pressed("inventory"):
        if visible:
            close()
        else:
            open()    

func close():
    visible=false
    
func open():
    visible=true

func update_inv_ui():
    for i in range(min(ui_slots.size(), inv.slots.size())):
        ui_slots[i].update_slot(inv.slots[i])

func use_item(item:itemSlot):
    drop_item(item)
    # Afegir condicionals per als diferents items segons el nom. Per exemple:
    # if (item.item.name=="key"):
    #     use_key.emit()
    
func drop_item(item:itemSlot):
    if item.amount>1:
        item.amount-=1
    else:
        var index=0
        while(index < inv.slots.size()):
            if inv.slots[index]==item:
                inv.slots.remove_at(index)
                break
            index+=1
    update_inv_ui()

Què fa en resum? Captura quan polsem la tecla assignada al mapa d'accions ("inventory") per obrir o tancar la UI, escolta si algun botó ha emès els senyals use i drop, i automàticament refresca les quantitats i les icones en pantalla.

4. 🎒 L'Aina i la seua Motxilla: La connexió final

Per a que tot el sistema que hem programat funcione, l'Aina ha de ser la propietària de la informació i de la interfície.

1. Equipant l'Aina (Nodes i Recursos)

Dins de l'escena del nostre personatge (Player.tscn), hem de fer dos passos fonamentals:

  • Afegir la UI: Arrossegueu l'escena InventariUI.tscn dins de l'Aina (millor si està dins d'un node CanvasLayer per a que no es moga amb la càmera i sempre aparega al centre de la pantalla de forma perfecta).
  • Assignar les dades: Creem la variable inventory amb @export a l'script de l'Aina i, a l'Inspector d'aquesta, hi afegim el recurs playerInv.tres arrossegant-ho. D'aquesta manera, l'Aina ja "té" una motxilla física on guardar coses de colp!

2. La funció de Recollida (collect)

Dins de l'script de l'Aina, necessitarem una funció anomenada collect.

  • Què fa?: Aquesta funció serà la "porta d'entrada". Quan l'Aina trobe un objecte al món, aquest objecte li "passarà" el seu fitxer .tres corresponent.
  • Com funciona?: La funció agafarà eixe fitxer en brut i cridarà al mètode update_inv de la nostra motxilla per a guardar-lo oficialment dintre a tota màquina.

🌍 Objectes al Món: El camí del .tres

Perquè l'Aina puga recollir una clau o una poció saltant per l'escenari, l'objecte que veiem a la pantalla ha de tindre obligatòriament dues coses preparades:

  • Una imatge (Sprite2D) i una Area2D amb forma: Per a que el joc sàpiga on està l'objecte i quan el toquem.
  • El seu propi fitxer .tres: A l'script de l'objecte del terra, hem de tindre un buit en l'Inspector de la variant de l'export per a posar el recurs de l'ítem (per exemple, li arrosseguem el nostre fitxer clau.tres o pocio.tres).

El flux per lo tant és el següent:
L'Aina entra a l'Area2D de l'objecte ➔ L'objecte llança la dada i diu: "Ei, Aina! Soc una clau, ací tens el meu recurs .tres!" ➔ L'Aina crida a la seua pròpia funció collect() de passada i el guarda ràpidament. Bam!

5. 🗝️ El Repte: La Porta Bloquejada

Ara que ja sabem recollir objectes, anem a posar-ho a prova amb un trencaclosques clàssic.

Com fer que una clau òbriga una porta?

La clau per si sola no sap obrir portes de manera mecànica; necessitem que hi haja una comunicació entre la motxilla de l'Aina i l'escenari.

  • L'Acció de l'Usuari: Quan obrim l'inventari i cliquem en "Usar" sobre la clau d'or, l'inventari ha d'emetre eixa nova senyal explícita (per exemple, la senyal use_key).
  • L'Escenari escolta: Heu de connectar eixa senyal única de la UI (que actualment està dins de l'Aina) amb l'script del vostre nivell principal o directament a la mateixa porta.
  • La Condició: La porta només s'ha d'obrir o destrossar (fent queue_free() o ocultant-se) exclusivament si s'ha rebut la senyal d'ús de la clau màgica.

🛠️ Tasca Pràctica 10: Programant l'Inventari

El vostre objectiu és:

  • Crear un recurs .tres per a una Clau.
  • Col·locar una clau a l'escenari que l'Aina puga recollir (ha de tindre la seua respectiva Area2D i codi de recollida).
  • Dibuixar una Porta (o un mur invisible) al Tilemap o a l'escena que ens impedisca continuar o passar.
  • Programar la lògica perquè, en usar la clau des de l'inventari mentre estem prop de la porta, aquesta desaparega o es desbloquegi completament.

💡 Pista per a experts: Haureu de connectar la senyal use_key que emet l'inventari de l'Aina amb l'escena del vostre nivell. Penseu bé en quin node està escoltant a quin!
